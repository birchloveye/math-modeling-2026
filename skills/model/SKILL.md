# 候选模型竞技场

开始前必须确认问题契约已得到明确人工批准。只读取已批准契约、紧凑数据摘要，以及与 `problem_type` 匹配的专家文件。

当题目确实支持足够差异时，生成三至四条实质不同的路线。不得把装饰性变体拆成多个路线，也不得在缺少有意义模型族时凑数。可信时应包含经典可解释方案；统计／数据驱动、机制、优化、仿真或创新方案必须在假设和验证行为上真正不同。

每条路线写入 `workspace/models/candidates/` 下的独立 JSON 文件，并符合 `schemas/model.schema.json`。不要编写实现代码。用紧凑比较表呈现问题适配、数学合理性、数据要求、可验证性、实现成本、鲁棒性、解释性、创新潜力和最大风险。

在 `gates/model_gate.md` 停止。只有一至两条明确由人工选定的路线可以继续。
